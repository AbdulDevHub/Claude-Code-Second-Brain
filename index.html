HOW THIS BRAIN WORKS

      
Every node is a real file Claude reads before it works: global rules, per-project memories, notes, skills, mods, MCP servers and sub-agents. Parked tools that are switched off in Toolbox appear too, drawn with dashed rims. A build step turns that folder into a graph. Seven hand-written layouts (a dotted 3D orb, a force-directed 3D graph, four 2D maps and a timeline) place it, and a canvas renderer draws it with thousands of dust particles at 60 fps. There's no graph library or WebGL framework.

      

      

      
    
        
  • Custom 3D force engine. Many-body repulsion, Hooke springs with degree bias, gravity and soft collisions, cooled on an alpha schedule. Same model as d3-force, rebuilt for three dimensions.
    • 
        
  • Perspective orbit camera. Every camera property eases toward a goal, so fly-to, follow, zoom, pinch and auto-orbit share one code path.
    • 
        
  • Morphing dust. Every layout writes the same number of seeded particles, so switching views morphs one cloud into the next point by point. They're batched by color and brightness into a few dozen fills per frame.
    • 
        
  • Fast glow pipeline. Glows, hex badges and icons are pre-rendered once and stamped with additive blending, so there are no per-frame gradients for the heaviest layer.
    • 
        
  • Privacy by construction. Five ordered redaction rules scrub emails, usernames and home paths, and the build refuses to ship if anything slips through.
    • 
        
  • Knowledge-graph extraction. A YAML frontmatter parser, a [[wikilink]] and relative-path resolver, and mention detection across every document.
    • 
        
  • Live, not hand-made. Running npm run open rescans the whole folder in a fraction of a second. The graph grows as Claude learns. node:test suites cover the parser, redaction, MCP secret handling, malformed config files, the camera math and every layout.
    •
